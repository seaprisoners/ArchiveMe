# Redesign the website (beginner-friendly)

Edit **[`web/src/styles.css`](../web/src/styles.css)**, not generated `web/dist/` files. It is a compact structural foundation rather than a finished theme: no imported font, gradient, shadow, animation, or decorative branding. You can change the look without editing JavaScript or backend code; keep readable controls, responsive navigation, and visible keyboard focus.

## Make a small change

1. Open the stylesheet and find `:root` at the top. Its editable variables are `--page` (page background), `--surface` (panels), `--text` (main text), `--muted` (secondary text), `--border` (outlines), `--accent` (actions), `--accent-text` (text on actions), `--focus` (keyboard focus), `--chart-track` (chart tracks), and `--space` (spacing). Change one value, for example `--space`, then save. Keep text and backgrounds legible; check `--accent-text` against `--accent` and make the focus indicator easy to see.
2. For a local change, use the stylesheet's section headings: **Base** (page defaults), **Buttons and inputs**, **Login**, **Dashboard** (navigation), **Overview and charts**, **Media and messages**, **Settings**, and **Mobile** (narrow screens). A selector is the name before `{`; the properties inside its braces control its appearance. Change one rule at a time rather than deleting a section: the styles support existing pages, charts, forms, thumbnails, and mobile navigation.
3. In a terminal at the project root, build with `npm --prefix web run build`. Refresh the **existing** app at `http://localhost:3000/` (the running Express server); do not start a second web server. Check sign-in and, as an authorized manager, Overview, Message archive, Statistics, Media & stickers, and Channel settings. Also check a narrow mobile width: menu, forms, chart labels, and message text should remain usable.
4. Repeat in small steps; undo a change if it breaks something. Review with `git diff --check` and `git diff -- web/src/styles.css`; run `npm test` before committing. Do not commit `.env`, `data/`, or generated `web/dist/`. Test only with a consenting server and invented messages; there is no synthetic preview button.

## Keep behavior and privacy intact

CSS changes must not hide important labels, counts, errors, permission cues, or keyboard focus. In Statistics, “Most active hours” counts messages by UTC hour for the chosen channel and period. “What messages contain” gives each message one category in order: video attachment, image attachment, URL, other nonempty text, then Other (including sticker-only or unrecognized attachments). Older records without classification stay Older / unclassified. Bars show relative counts; labels and numbers should remain readable without bars.

Media & stickers shows attachment/sticker details, available Discord links, and captured emoji metadata. Popular counts are metadata, not stored files. Safe thumbnails load directly from approved Discord hosts; validated, size-limited Lottie JSON can render in the browser. Links may expire, older records may lack media/emoji details or sticker format, and names/counts must remain readable without previews. ArchiveMe does not fetch, store, serve, or download binary media files. New preview sources or local downloads need separate privacy, authorization, and storage review. The bot-install link is not human sign-in and does not enable archiving. If you later edit [`web/src/main.jsx`](../web/src/main.jsx), never render untrusted archived text as raw HTML or remove permission checks.
