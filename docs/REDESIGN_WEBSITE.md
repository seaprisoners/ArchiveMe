# Redesign the website (beginner-friendly)

Edit **[`web/src/styles.css`](../web/src/styles.css)**, not generated `web/dist/` files. It now has a simple design: plain panels, readable text and obvious controls, with no custom illustrations or decorative slogans. Layout rules keep the dashboard, charts, media and mobile navigation usable. You can change the appearance without editing JavaScript or backend code.

## Make a small change

1. Open the stylesheet. At the top, change `--page`, `--panel`, `--text`, `--muted`, `--line`, `--action`, `--action-text`, `--focus` and `--chart` to your colors. For instance, change `--action: #174b77` and save; buttons and links update after building. Make sure text contrasts with its background and keyboard focus stays visible.
2. Find an element's section: **Base**, **Buttons**, **Login**, **Dashboard**, **Statistics and charts**, **Media and message archive**, **Members**, **Settings**, or **Mobile**. A selector is the name before `{`. Change one rule at a time rather than deleting the positioning rules: the stylesheet still makes features usable without prescribing their appearance.
3. In a terminal at the project root, build with `npm --prefix web run build`. Refresh the **existing** app at `http://localhost:3000/` (the running Express server); do not start a second web server. Check sign-in and, as an authorized manager, Server archive (all enabled readable channels or one selected channel, with media and UID), Statistics, Media & emotes, Members, and Channel settings. Also check a narrow mobile width: menu, forms, chart labels, and message text should remain usable.
4. Repeat in small steps; undo a change if it breaks something. Review with `git diff --check` and `git diff -- web/src/styles.css`; run `npm test` before committing. Do not commit `.env`, `data/`, or generated `web/dist/`. Test only with a consenting server and invented messages; there is no synthetic preview button.

## Keep behavior and privacy intact

CSS changes must not hide important labels, counts, errors, permission cues, or keyboard focus. In Statistics, “Most active hours” counts messages by UTC hour for the chosen channel and period. “What messages contain” gives each message one category in order: video attachment, image attachment, URL, other nonempty text, then Other (including sticker-only or unrecognized attachments). Older records without classification stay Older / unclassified. Bars show relative counts; labels and numbers should remain readable without bars.

The Server archive shows authorized enabled channels together, with text, available media, stickers and emotes; Media & emotes offers a separate list of captured details. Popular counts are metadata, not stored files. Safe thumbnails load directly from approved Discord hosts; validated, size-limited Lottie JSON can render in the browser. Links may expire, older records may lack media/emoji details or sticker format, and names/counts must remain readable without previews. ArchiveMe does not fetch, store, serve, or download binary media files. New preview sources or local downloads need separate privacy, authorization, and storage review. The Members tab searches Discord's current member information by full UID or name prefix; it is not a stored roster and may depend on Discord permissions and availability. The bot-install link is not human sign-in and does not enable archiving. If you later edit [`web/src/main.jsx`](../web/src/main.jsx), never render untrusted archived text as raw HTML or remove permission checks.
